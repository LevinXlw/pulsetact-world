# MIT 现实场景设计方案 v2

日期：2026-09-15。状态：主楼柱廊第一阶段样板已实现；核心庭院扩展、植被、连续路线与完整性能验收仍待后续推进。实际改动和验证见 [柱廊样板交付](portico-v2-delivery.md)。

本方案以当前室外演示版为起点。已完成内容以 [2026-09-15 交付记录](mit-realism-delivery.md) 为准；[上一轮改造计划](mit-realism-roadmap.md) 保留为历史记录。

## 1. 目标与默认方向

将 MIT 的核心校园区域做成可以在地面连续行走、停下观察的真实校园环境。第一眼能认出 MIT，走近后能看清建筑构造，转身和移动时仍保持可信的空间、材质和光影。

默认设计条件：桌面浏览器、现有 React / Three.js 技术栈、本地资产；采用树叶繁茂的夏末至初秋白天，柔和而有方向的日光。季节和光照是美术设定，照片中的拍摄季节与时间另行记录，不推断所有参考拍于同一天。

首轮交付一段核心路线：**Killian Court 南侧步道 → 主庭院 → 10 号楼台阶与柱廊 → 西侧庭院树荫步道 → 返回南侧并连接 Memorial Drive 河岸。** 地理连通和道路过街位置以现有坐标及官方地图核对，桥面细化在后续扩展中完成。

以这段路线上的建筑、地面、植物、光影和人的尺度共同定义画面质量。其他区域继续提供校园空间背景，按观察距离逐步扩展细节。

## 2. 当前画面的具体诊断

本节来自现有模型代码、2026-09-15 截图与 MIT 官方照片的对照，是设计判断。不同机位、焦距、曝光和拍摄年份会影响观感；当前图片不构成测量级配准。

| 观察到的问题 | 现有基础与原因 | 下一步改变 |
| --- | --- | --- |
| 主楼显得过于整齐、均匀 | 已有柱廊、凹槽、门组、铭牌和檐口；大量尺度由程序参数推定，表面主要使用通用扫描材质与规则分缝 | 校准轮廓、柱头、檐口与开口比例；根据构造位置加入石块差异、积尘和雨水痕迹 |
| 两翼像重复拼装出来的建筑 | 当前共 2,380 组窗格，3/4 等楼使用通用规则；部分窗框叠在原墙面前 | 按建筑与立面分别制作开口表，近景替换墙面并制作真实窗洞、窗台、侧壁及玻璃后退 |
| 玻璃偏一块暗蓝平面 | 已有一次性环境反射探针，材质变化和室内遮挡层次少 | 保留反射，补窗洞阴影、浅层室内遮挡和克制的窗间差异；反射探针按区域布置 |
| 草地像铺开的纹理 | 庭院已覆盖独立地面，但地表颜色、尺度和边缘变化不足 | 草坪基底、自然块状色差、近处草簇、步道收边分层制作 |
| 树木近看有硬质几何片感 | 81 个位置、41 个树冠分块和距离分级已经存在；叶簇为程序化三片尖叶，树干偏简单 | 制作少量高质量树形原型，先替换视线附近的树；增加枝条层级、树皮、叶片轮廓与透光 |
| 柱廊和树荫的明暗偏生硬 | 已有 4K 动态阴影与 SSAO，但材质、环境补光和遮蔽尚未联合校准 | 统一日光和环境光；加强间接光与接触关系，校验阴影稳定性 |
| 仍有地图查看器的感觉 | 已有环境展示，但固定机位按钮多，展示模式会切到 orbit，角色漫游又退出展示 | 增加简洁的第一人称环境漫步，让地面观察与连续行走使用同一体验 |

现有 1.65 米观察机位、基础步行路线、gzip 渐进加载、树冠失败恢复、环境遮蔽均继续使用。本轮重点是提升资产本身的可信度及系统间的一致性。

## 3. 空间制作范围

### A 区：第一批高质量核心

Killian Court、10 号楼朝向庭院的立面和柱廊，以及 3/4 号楼朝向庭院的可见立面。

先选定主楼中部的一组完整构造作为样板：从草坪/铺装到台阶、柱脚、柱身、柱头、门窗和檐口。它必须同时从庭院、台阶上和侧向三个位置成立。单元通过后扩展至完整主立面，再制作 3/4 号楼。

10 号楼与 3/4 号楼共同围合 Killian Court；官方说明还确认主楼的十根爱奥尼柱采用轻微外弧排列。这些都是校准建筑识别度的依据。[MIT List 建筑资料](https://listart.mit.edu/art-artists/maclaurin-buildings-1913)

### B 区：连续体验走廊

西侧庭院作为首选：完善树荫、地面、墙根和少量设施；参考采集若显示东侧资料更完整，可在制作开工前替换为东侧。路线回到南侧后连接河岸，重点是过街、步道、水边和远景层次。

核心路线所有可达位置都要有可信的地面与碰撞。没有精细制作的门口仍作为封闭外立面展示；真实室内另设后续项目。

### C 区：背景校园

其余建筑保留 GIS 坐标与体量，逐步按照片分类为不同墙面、窗型和屋顶。优先解决沿路线可见的白墙、错误窗格和突出的近景屋顶。远处采用简化模型，不以整校统一高精度作为本轮完成条件。

建议制作距离起点：0–30 米检查门窗、地面和枝干；30–150 米检查立面节奏、树群和主要结构；150 米以外检查轮廓与颜色。距离分级最终结合屏幕占比调整，楼顶或大树不会仅因距离远就过早消失。

## 4. 美术设计规范

### 建筑：先校准构造，再增加细节

1. 为 10/3/4 号楼建立独立立面描述，记录层线、轴线、开口、窗台、石材层次及其参考出处。由同一描述生成详细、中等和背景版本。
2. 校准穹顶弧线、鼓座高度、檐口分层、柱列与墙面的前后关系。现有测绘坐标作为底座；需要修正时记录差值和依据。
3. 近景采用有厚度的窗洞、门洞和窗台，消除窗框贴在实心墙外的感觉。更换详细面时移除重叠的基础面，避免闪烁与重复投影。
4. 以浅灰米色石材为主，分清柱身、台阶、墙块、金属与玻璃的粗糙程度。石材颜色的细微差别按块面和构造分布。
5. 表面痕迹集中于有成因的位置：檐口下方、窗台滴水处、墙根、台阶常走区域；强度克制。避免把同一噪点平均撒满整面墙。
6. 铭文、浮雕和柱头先保证实际观察距离下的轮廓与阴影，再决定是否增加几何。远处细节烘焙为法线或颜色信息。

MIT 官方穹顶修复报道明确提到石灰石覆面，因此穹顶材质应按石材制作；色差和风化强度仍需由照片确认。[MIT News 修复记录](https://news.mit.edu/2013/great-dome-reborn-oculus-0215)

### 地面：让脚下的尺度成立

- 核心路线使用单独制作的铺装、路缘、草坪和台阶，航拍主要作为定位与远景底层。
- 铺装以真实铺设方向、分缝、边界及局部修补组织；尺度由有尺寸线索的参考确定。
- 草地拆为基础材质、较大范围色差和近处稀疏草簇。树根和路边有过渡，不做整片均匀的毛毯。
- 树池、墙根与路缘建立明确接触关系；将排水口等小构件放到参考可确认的位置。
- 河岸先解决岸线、步道和水面的高度关系，再调整波纹与反射；道路上的车辆影像不作为近景物体使用。

### 植被：先做少量可信树木，再扩大覆盖

- 建立 3–5 个不同树冠结构与年龄的阔叶树原型，先完成其中 1 棵作为样板。树种名称必须有依据，资料不足时记录为树形近似。
- 树干有锥度、主枝、次枝和根部过渡；树冠按枝条生长关系成簇，留有能看见天空的自然空隙。
- 近处使用真实叶片轮廓贴图与树皮材质，结合适量几何；叶片采用透明裁切，检查过度绘制、阴影和边缘闪烁。
- 叶面保留明暗和朝向差异，背光时有适度透光；所有树、草的轻微摆动共享风向，减少运动设置可关闭。
- 沿核心路线先替换约 8–12 棵视觉影响最大的树作为初始范围，其余沿用背景树。数量在参考和机位确认后冻结，不当作质量指标。
- 当前 81 个位置作为初始清单。位置调整要附对照依据，同时验证步道通行，不将上一版的位置误认作测量结果。

### 光照：自然白天、固定基准

- 锁定一套夏末至初秋白天基准，主楼受侧向日光，柱廊有阴影但能读到门窗。天空可见亮度、补光与玻璃反射使用一致的环境。
- 先在中性材质下确认阴影和比例，再校准石材、草地与树叶。曝光对整条路线保持稳定。
- 静态建筑可烘焙间接光或遮蔽；动态日光继续负责主要方向阴影。避免把同一份直接日照同时烘焙并实时叠加。
- 保留已有 SSAO，先检查它与烘焙遮蔽是否重复变黑。若柱廊小构件仍不足，再试验局部阴影范围或级联阴影，依据移动时的稳定性决定。
- 玻璃按庭院、柱廊、侧庭院划分少量本地反射探针；不逐窗实时渲染反射。
- 不设置默认强景深、重暗角或大面积辉光；以清晰的正常步行画面验收。

### 生活感与观看方式

建筑和景观达标后，补少量参考明确的长椅、自行车架、路灯和校园标识。低密度路人、自行车以及环境声音可增加生活感，但采用独立开关并安排在后期；移动物体的形体、比例和动画需要与环境相容。

提供「环境漫步」与「角色探索」两个入口，复用同一世界：环境漫步采用约 1.65 米第一人称镜头，视角初值保持现有 48° 垂直 FOV，允许小范围调节；角色探索保留第三人称与既有任务。

环境漫步默认收起任务、人物标记和长机位工具条，只保留退出、地点、拍照和设置。固定对照机位放入独立菜单；原始模型对比留在检查入口。首次进入不强制锁定鼠标；启用鼠标锁定时由明确点击触发，Esc 可退出。

## 5. 参考采集与资产制作

### 首批参考包

| 对象 | 已有材料 | 制作前需要补齐 |
| --- | --- | --- |
| 10 号楼主立面 | MIT List 三张官方照片、旧正面照片、GIS 轮廓 | 同一时段或相近时期的左右斜视、柱头/柱脚、台阶、门窗与石缝近景 |
| 3/4 号楼庭院立面 | GIS 体量、当前通用立面 | 每栋正视、斜视、转角和窗型细节，明确哪些面已覆盖 |
| 主庭院与西侧庭院 | 航拍、现有地面与树位清单 | 行人高度的铺装、草坪边界、树形、树根和设施位置 |
| 南侧道路及河岸 | GIS 与平面分类 | 地面视角的过街位置、路缘、护栏、岸线与水面关系 |

MIT 官方校园地图用于核对建筑编号与空间关系；设施部门的部分楼层图有访问限制，不把它们作为必需的公开素材来源。[MIT Facilities 地图说明](https://web.mit.edu/facilities/maps/index.html)

每条参考记录包括：对象、立面/方向、来源 URL、本地文件、已知拍摄日期、可用尺度线索、允许的用途、未确定部分。把「GIS 测绘」「照片校准」「视觉近似」记录到具体部位。

现有 MIT 图片用于视觉参考。运行时纹理采用自己制作或用途明确的扫描素材；具体资产沿用项目来源记录，不自动将参考照片纳入游戏贴图。若补充现场采集，先针对少量构件做多角度重建试验，再判断是否扩大。

### 建议生产流程

参考与相机匹配 → GIS 定位 → 立面/地面样板 → 材质与光照校准 → 详细与简化模型 → 压缩导出 → 浏览器实际行走检查。

采用 Blender 或同类 DCC 制作近景构件、UV、烘焙和 LOD，脚本负责放置、重复生成和验证；源工程随资产保存。继续使用 GLB 接入现有渲染器。安装与可用工具在实施时检查，本方案未安装软件或采购资产。

生成式模型可作为小型道具候选，需要修整比例、拓扑和材质。建筑主要轮廓、门窗、柱廊仍由测绘与照片控制。在线摄影测量或点云展示可作为未来独立评估路线；当前先完成能碰撞、能行走、能维护的本地网格场景。

资产按区域或建筑组织，共享材质与重复构件；避免把全校园所有石材合成一个巨大对象而失去有效剔除。门窗、草簇和树原型优先复用实例，同时检查实例分组范围。

模型可试验 Meshopt 压缩，材质优先试验 KTX2/Basis。现有 Three.js 0.176.0 的本地加载器已经提供 `setMeshoptDecoder`、`setKTX2Loader` 接口；具体导出格式必须在当前锁定版本验证，不为此默认升级整个依赖树。解码文件也从本地提供。[GLTFLoader 官方说明](https://threejs.org/docs/pages/GLTFLoader.html) · [KTX2Loader 官方说明](https://threejs.org/docs/pages/KTX2Loader.html)

gzip 降低传输体积，解压后的几何仍要占用内存；几何精简、实例化和 GPU 压缩纹理分别处理不同成本。`InstancedMesh` 可减少相同几何与材质对象的绘制调用，但不保证降低透明叶片的像素开销。[InstancedMesh 官方说明](https://threejs.org/docs/pages/InstancedMesh.html)

| M3：连续路线与观看方式 | 侧庭院、南侧连接、河岸、环境漫步、少量设施 | 全程连续录屏；地点与任务可恢复 | 核心路线无穿地/阻塞，相机和碰撞稳定，正常视角可读细节 |
| M4：性能与交付 | 区域加载、模型/纹理压缩、资源释放、完整回归 | 两档画质、实机性能报告、来源清单、机位对照 | 达到约定设备性能预算和功能验收，剩余近似部分明确 |

性能采样从 M0 开始，每阶段观察增量。M4 用于最终收敛。工期取决于参考完整度和样板返工，先完成 M0/M1 后再估完整路线工时，避免用未经验证的天数承诺写实质量。

首批执行顺序：冻结当前资产与代码快照 → 补主楼样板参考 → 匹配三个观察机位 → 制作完整样板 → 核验画面和性能 → 扩展。当前目录没有 Git 仓库，实施前建立可回退基线；不需要先进行大规模目录重构。

## 8. 验收标准

### 视觉与空间

- 固定六个主机位：庭院主楼、台阶柱廊、3 号楼立面、4 号楼立面、西侧树荫、河岸步道。新增机位保存位置、目标、FOV 和地面高度，不把当前 `facade`（6 号楼）误当作 3/4 号楼。
- 同一机位保存当前版本、改造后版本；实拍放在旁边并注明相机匹配程度。不同曝光或光照的图片不直接作为材质颜色测量。
- 10/3/4 号楼的可见轮廓、层线、门窗排列与参考对应；无法确认的部位在资产清单记录。
- 在地面约 1.65 米观察时，窗洞有进深，柱脚和台阶接地；前进、转头后不出现面片重叠、反光跳变或漏光。
- 核心路线无明显烘在地面上的树冠、车辆和重复阴影；草地与铺装边界自然，树木近看有可辨识枝叶结构。
- 在无任务标记的正常漫步画面里验收；辅助效果关闭后仍能看清几何和材质。
- 完整路线全程键盘走通，录屏覆盖转弯、台阶、阴影到日光的过渡、过街和河岸。

### 性能：以下是待验证的设计预算

M0 先记录实际电脑、GPU、浏览器、分辨率和电源模式，标准验收基准拟采用 1920×1080、DPR=1 的真实浏览器窗口。测试时不并行运行其他渲染任务。

| 指标 | 初始目标与测量方法 |
| --- | --- |
| 行走稳定性 | 模型就绪后沿核心路线连续 10 分钟，帧间隔 p95 ≤33.3 ms，争取接近 60 FPS；另记长帧和卡顿分布 |
| 首次交互传输 | 包括代码、基础模型、贴图和必要解码器，首个可走场景目标 ≤20 MB；后续细节继续加载 |
| 核心区域完整传输 | 暂定 ≤35 MB，M0 测完整请求后复核；不用仅增强文件的体积代表总下载量 |
| 加载时间 | 清缓存、20 Mbps / 50 ms RTT 条件下，首个可走场景目标 ≤15 秒；同时记录解码与上传时间 |
| 资源释放 | MIT / Harvard 往返 10 次及视角切换后，几何、纹理与 JS 内存无持续增长趋势 |
| 低画质 | 使用相同可走区域，降低植被、阴影和后处理；首轮在实际设备上确定帧率目标 |

浏览器资源计数不能直接充当精确显存字节数；显存预算用纹理格式、尺寸、mipmap、几何缓冲和渲染目标估算，报告方法。当前 Headless Chrome 的 3 秒采样仅作历史背景，不直接证明上述目标已经达成。

### 功能与恢复

保留两校故事、收藏、活动、照片和本地存档；验证角色与环境模式切换、对话暂停、低画质、原始模型对照、树冠失败和无 WebGL 航拍降级。资产加载后断开外网仍能浏览已加载路线，本地服务器继续运行。

修复或明确完整 Playwright 命令停在启动阶段的问题，形成可重复执行的入口。视觉检查、加载异常和真实键盘路线复用已有脚本；每次变更运行受影响的验证，最终执行完整验收。
